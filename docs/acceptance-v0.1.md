# v0.1 验收矩阵

状态：设计验收标准，尚未执行。范围：macOS、原生 Windows/PowerShell；Go；Git 仓库；原生 Codex CLI；不使用 MCP。

验证顺序：G0 原生会话接入 → G1 模拟执行者可靠性 → G2 真实 CLI 适配 → G3 Git 与清理闭环 → G4 发布与资源测量。

每条用例记录操作系统、架构、文件系统、Codex/daemon/执行 CLI/本工具/Go/Git 版本、输入、实际输出及证据位置。仅通过帮助文本或协议 schema 不能标记端到端用例通过。方法依据：[G0 实验规格](g0-validation-plan.md)、[运行协议](runtime-protocols.md)、[Git 与清理协议](git-cleanup-protocol.md)。

## G0：原生会话接入，先决条件

| ID | 情境 | 通过条件 |
|---|---|---|
| C01 | 用户直接运行 codex | 正常安装及原生Hook信任后，标记轮次证明是同原服务同thread；不需要替代启动命令、不修改Codex本体 |
| C02 | 同仓库两个不同会话 | 任务绑定明确的会话身份；任一结果只送给所属会话，不按 cwd 或最近活跃记录猜测 |
| C03 | 同一会话多客户端/旧发送者暂停后恢复 | 唯一交付者串行协调；接管前确认旧socket不能再提交并对账，不只看租约；重复展示不得重复副作用 |
| C04 | busy及用户新输入与回调同时到达 | 覆盖用户先到/结果先到/idle→busy竞争；用户消息不丢失覆盖，回调保持工具结果身份，顺序可由原服务解释；旧action被新revision拒绝 |
| C05 | Codex 空闲但界面仍打开 | 完成/阻塞事件能够自动触发原会话继续处理，无需用户输入“继续” |
| C06 | CLI 正常关闭 | 已执行任务继续；待回调持久化；不因 loaded thread 仍存在就唤醒离线主控 |
| C07 | 终端或 CLI 被强制终止 | 不能依赖 SessionEnd 必然执行；执行者继续且无跨会话投递 |
| C08 | 用户恢复原会话 | 补交尚未处理的结果；既不漏交，也不重复整合或重复派发 |
| C09 | 会话压缩、clear、fork及fork内新工作流、子AgentHook | 绑定发起工作流的具体controller_thread_id，不误转tree根；压缩保留绑定，子Agent不抢主控，新身份不自动继承旧操作权 |
| C10 | 关闭与回调同一时刻发生 | 交付有明确提交边界；已获接收的回调与仍在本地待交付的回调可区分；不声称跨系统绝对原子性 |
| C11 | RPC/历史/业务ACK各阶段丢失与部分ACK | 按G0屏障三态对账；改变command UUID仍不能重复副作用；运输已确认与业务ACK分离，不让进展挡住问题；uncertain不盲重发 |
| C12 | 不支持版本、Hook未信任/禁用/策略禁止/定义改变 | 创建执行前拒绝并给出缺失条件；不代批Hook，不退化为键盘模拟、修改聊天文件或新建主控 |
| C13 | 桥接连接、投递与必要resume前后 | 公开非凭据的有效模型/provider/权限/环境保持一致，原生审批和问题可正常回答；RPC不覆写sticky设置 |

## G1：模拟执行者与调度可靠性

| ID | 情境 | 通过条件 |
|---|---|---|
| R01 | 3 个可执行任务到达 | 默认只有 2 个执行者同时运行；排队任务显示 queued，不算运行超时 |
| R02 | A→B 与独立 C | A 与 C 可并发；B 仅在声明的依赖产物达到就绪条件后运行 |
| R03 | 进程长期无 stdout | 显示缺少新进展，执行诊断；不直接认定失败，不伪造进度 |
| R04 | 只有 supervisor 心跳 | 只能更新存活信息，不能更新 last_progress 或用户里程碑 |
| R05 | 运行较久但持续产生有效进展 | 软预算到期仅提醒/检查；不以预计耗时直接杀死任务 |
| R06 | 执行者报告需要技术决策 | 提问持久化并关联 question_id；Codex 回答后仅恢复对应执行；重复答案不重复执行 |
| R07 | 原生权限请求/拒绝 | 独立于技术问题处理；不替用户批准、不切到更宽权限规避拒绝 |
| R08 | 退出码 0 但任务未完成 | 状态为部分完成/阻塞/待审查等实际状态，不直接判为成功 |
| R09 | 超时/取消后重试 | 确认前一执行树停止并记录现场后才发新 attempt；旧 attempt 事件不能改写当前状态 |
| R10 | 失败并切换 CLI | 最多 3 次执行尝试；技术问答续接不机械增加尝试数；认证失败不触发登录操作 |
| R11 | coordinator/Host崩溃或机器重启 | 按意图、屏障、spawn、DB提交、ACK各窗口注入；已durable确认事件不丢，UNKNOWN持槽不重跑，活动Host有限退避恢复协调器 |
| R12 | 同时首次派发/同时启动后台进程 | 单实例选主；数据库事务和持久化派发意图避免重复启动 |
| R13 | 大量或超长输出 | 仅schema允许日志有界流式写盘，未知raw不落盘；内存有界、截断可见，关键事件走独立队列 |
| R14 | 用户主动停止/撤回任务 | 晚到事件不能自动重新派发、整合或唤醒已撤回工作流 |
| R15 | 等待技术答复或用户处理权限 | 分段退出整棵已拥有执行树后才释放槽；不以OS暂停释放；续接新segment重新获槽，存活/UNKNOWN仍占槽 |
| R16 | 非法DAG、并发改计划、上游失败/取消 | 整次计划事务校验；非法图不部分派发；必要下游blocked_dependency，独立工作继续 |
| R17 | 依赖换版与任务改名/拆分并行 | 实际快照不偷换；旧成果stale不得认可；共享预算组不重置，segment额度事务预占，组内并行不重复授额 |
| R18 | 多run持续入队、retry/resume与配额下调 | ready_sequence FIFO，retry/resume队尾；默认用户级总2；下调不新增超额执行且不强杀 |
| R19 | 共享预算组并行、硬预算到期且协调器离线 | Host只执行获授持久额度，确认退出才结算退还；UNKNOWN不退；跨segment/attempt/重启累计不超授额 |
| R20 | 系统时钟/休眠、退避重启和第三次失败 | 不通过时钟或重启重置预算/next_retry_at；最多三attempt，无法证明未运行的预占不退回 |
| R21 | 同/冲突/旧版本/显式改版答案、取消与续接ACK丢失 | Question状态与slot正确；启动outbox领取/prepared/UNKNOWN边界修改答案不能产生同attempt双写者，未确认旧树退出不建后继 |
| R22 | 孙进程写入、忽略取消、setsid/Job限制、PID复用 | 只管理已证实拥有的树；不以父退出/kill返回推断全停；异常归属不自动重跑或清理 |
| R23 | Host spool/DB durable ACK前后崩溃 | 每事件先durable写Host；DB事务提交后才ACK；重复hash冲突可见，不删除未ACK关键事件 |
| R24 | 巨行/未知输出、控制通道洪峰、磁盘满 | 使用既定大小/容量线；关键状态不被日志挤掉，截断可见，未提交不ACK；磁盘彻底满不伪称已保存错误 |
| R25 | 并发submit、Host启动ACK丢失、数量上限和结果待交 | 创建前事务预占Host槽，starting/UNKNOWN仍占；超限admission_deferred，不补用其他认证上下文；无执行用途Host在事件ACK后退出 |

## G2：账号、权限与真实 CLI

| ID | 情境 | 通过条件 |
|---|---|---|
| A01 | 现有账号可直接运行 CLI | 调度沿用该 CLI 正常的认证与权限行为，不需要另配置 API Key |
| A02 | argv/env、桥接RPC及模拟认证canary | 不新增认证/端点/计费/权限绕过设置，不持久化认证来源/完整环境；已知敏感事件过滤，未知raw不落盘；不声称识别任意任务文本秘密 |
| A03 | 集成安装和卸载 | 只新增/移除本项目的 Codex 集成文件与条目；保留用户原配置、账号和其他插件 |
| A04 | headless 权限与交互模式不同 | 如实记录支持边界；不通过 bypass 参数掩盖；必要时报告 permission_blocked |
| A05 | worktree改变目录trust和配置发现 | 用隔离夹具比较来源/祖先/项目/local配置影响的provider/端点/权限；不复制改写配置；不能保持来源连续性的组合不准入 |
| A06 | 自动选择/用户指定执行者、各CLI首次与续接 | 首次调用匹配用户指定或已认可的选择合同，后续换CLI遵守合同fallback范围；分平台验证读写、测试、提问、续接、失败与取消，不把缺能力称已适配 |
| A07 | Windows PATH 包含 exe/cmd/ps1 shim、空格和中文 | 参数不被错误拆分；仅在确实需要时使用明确的 shim 启动策略；不依赖 WSL |
| A08 | 关闭 PowerShell、父进程所在 Job 限制 | 执行者生命周期与已确认策略一致；取消能处理整个已拥有的执行树 |
| A09 | 两个来源会话具有不同 PATH/环境 | 不复用首次启动后台进程的环境；执行者沿用自己的来源上下文，不将整份环境或凭据写入 DB/日志；重启后上下文不可重建时等待重新绑定 |

账号配置边界的自动测试使用模拟配置和临时测试账号目录；真实联调不为“验证未改变”而读取用户凭据内容。底层 CLI 自行刷新自己的登录令牌，不等同于本工具管理凭据。

## G3：Git、审查与清理

| ID | 情境 | 通过条件 |
|---|---|---|
| W01 | 主工作树原有 staged/unstaged/untracked 文件 | 不 stash/reset/清理用户修改；任务基线明确；缺少必要未提交上下文时报告，不能静默按旧 HEAD 完成 |
| W02 | 独立与依赖任务 | 每个写任务独立 worktree；记录 base commit 和依赖版本，不能凭分支名隐式共享不断变化的产物 |
| W03 | 执行结束与组合冲突解决 | 清理后freeze commit并pin；TaskReview不能放行改变后的最终candidate，需IntegrationReview和对应验证 |
| W04 | 两项任务同时等待整合 | 每仓库整合串行；候选在实际目标基线上验证；不能把各自单测通过当作组合验证通过 |
| W05 | 审查后目标分支/工作树变化 | 重查目标状态和冲突；不覆盖用户修改；必要时重新验证或等待主控决定 |
| W06 | 临时脚本、测试报告和正式新增测试并存 | 按所有权与用途处理；删一次性脚本，保留正式测试和必要报告，不按后缀或文件名猜测 |
| W07 | 检查后替换父目录/链接/junction/同名文件 | 用句柄相对操作重新核验身份，不能只做字符串前缀校验；外部哨兵内容/身份不变，不明归属保留 |
| W08 | 删除被 Windows 进程占用的文件失败 | 有限重试，标记 cleanup_pending；不丢清理清单、不谎报全量完成 |
| W09 | 失败/待返工任务 | 保留必要现场，下一 attempt 能有依据接管；恢复材料不混入交付 diff |
| W10 | 成功交付与后续依赖 | 依赖解除且整合验证后回收 worktree、临时分支/脚本；交付代码和审查证据仍可定位 |
| W11 | 清理过程中崩溃 | 清理操作可重入，文件清单逐项记录状态；重启不误删归属不明文件 |
| W12 | update-ref式错误落地、merge完成DB未记账、旧Git仍活 | 实测ref/index/worktree三态；采用明确快进命令；成功补记、不确定保全，不自动reset或双merge |
| W13 | merge.autoStash=true、ignored及文件目录碰撞 | 显式no-autostash/no-overwrite-ignore拒绝覆盖；原文件/HEAD/index/stash列表不变 |
| W14 | 冻结后改worktree、测试依赖未入候选的ignored文件 | 候选commit仍可定位；从干净OID材料化验证，额外输入需合同化，不以旧目录测试冒充候选验证 |
| W15 | A→B+C、A替换/撤销、输入组合冲突 | B实际base tree含固定A；冲突不释放B；旧B变stale不能整合，独立C不受错误传播 |
| W16 | 创建前/创建后登记前/删除后ACK前崩溃 | write-ahead意图与文件身份对账；陌生同路径文件不删除，残留不静默遗漏 |
| W17 | worktree含ignored未知物、私有ref被改指向、对象被用户共享 | 整棵回收被阻止；不全仓prune/GC、不通配删refs/直接删objects；expected OID不符保留 |
| W18 | TTL/容量及资源级pin释放 | 仅剩OID依赖时可回收无可变用途worktree但保留ref/report；最后引用解除后到期可回收；未ACK/恢复不驱逐，cleanup回执不反向pin目录 |
| W19 | 预检查后外部切换分支或编辑、merge hook改变内容 | 检测integration_uncertain，保全实际状态；不宣称未写入、不自动reset；稳定目标条件单独记录 |

## G4：发布、资源和范围

| ID | 情境 | 通过条件 |
|---|---|---|
| P01 | 首次安装 | macOS、Windows 各有已测试产物；支持版本矩阵和卸载方式明确 |
| P02 | 完全空闲 | 按约定退出；不默认注册开机常驻服务 |
| P03 | 离线会话有待回调 | 本地可靠保存，不频繁唤醒模型；若暂时保留进程，事件等待不采用忙循环 |
| P04 | 0/1/2执行者、4Host上限及日志洪峰 | 达到运行协议冻结的RSS/CPU/延迟/磁盘通过线；与外部CLI分开报告，不能只测不判或事后调阈值 |
| P05 | 不受支持的操作系统/CLI 组合 | 明确列出限制；不能只因 Go 能编译就标记平台端到端支持 |
| P06 | 升级/卸载时有任务、回调或被改集成文件 | 版本并存/延迟破坏性卸载；binary/state以及恢复所需Hook/Skill/配置均受pin保护；不整份回滚，只改匹配条目 |
| P07 | 数据目录不可用、schema迁移中断、未知新schema | 不退回cwd/temp/cache；迁移可对账，不丢旧库；旧程序不猜读新schema |

## 当前证据等级

- 已确认：用户需求与约束；本地 Codex 0.153.4 的帮助和 toolOutput 协议字段；官方 App Server/Hooks 文档存在相关接口。
- 未验证：表中所有端到端行为、资源数据、Windows 真实运行及各 CLI 在既有权限下的完整能力。
- G0 未通过前，不能对外宣称“无需包装原生 Codex、实时自动回调、关闭恢复”已实现；不能通过改变账号权限或让用户改用新启动器绕过失败。
