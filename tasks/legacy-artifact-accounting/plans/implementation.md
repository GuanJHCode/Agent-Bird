Base `15c676a`, schema21. ROOT freezes the contract and integrates; assigned worker owns this isolated WT. No other writer in this WT. Do not revert unrelated edits. No descendants, model/account calls, native actors, installation changes, push/release, or user-data deletion.

## Contract

1. Add an immutable, data-only `legacy_artifact_claims` ledger, keyed by source class + durable source event ID. Preserve run/capability scope, original logical artifact declaration (JSON/hash), declared raw bytes and `legacy_pending` / malformed classification. No managed reservation/ref/intake or filesystem authority arises from this row. No filesystem reads/writes during migration. Control charge includes the ledger's actual bounded metadata; raw bytes count separately.
2. Valid legacy non-Exited runtime declarations, legacy report declarations, and legacy Host progress each contribute their own source claim. Exited has zero raw charge by the existing lifecycle contract, not by comparing paths as physical proof. Preserve event bodies byte-for-byte. No content/path-based merging of unrelated events.
3. Runtime original `host_artifact_verified` classification is immutable; migration excludes verified rows. Existing report/progress managed status must be proved by their exact durable ref/scope binding at migration time and frozen, never inferred only from embedded receipt presence. Public new report-with-artifact always uses verified intake. Do not invent a live unverified report path.
4. Split valid historical raw from control exactly once. `accounted_bytes` in report/progress becomes its prior value minus the actually charged legacy raw; retain question reserve and all control metadata. Capability used_bytes and storage_usage scopes must reflect the exact same split. Runtime UPDATE/DELETE refunds must use the original frozen classification; a later matching managed ref cannot change it. Preserve schema21 helper expressions for real historical downgrade fixtures.
5. Malformed/unclassifiable historical rows remain unchanged with a durable malformed sentinel and block new raw reservations; no guessed refund. Negative/fractional/missing/overflow sizes, insufficient prior accounted bytes, and malformed JSON require conservative handling. If a corrupt old counter cannot be preserved exactly, fail migration transactionally with the old DB intact rather than inventing a balance.
6. The 2GiB admission includes checked-add sums of every unreleased managed reservation plus valid legacy claims. Any malformed sentinel/overflow rejects new raw reservation. Legacy declarations neither become disk-outstanding promises nor grant retained/free-disk credit. Over-limit history migrates without deleting data and blocks further grants.
7. Late authenticated historical Host events may durably record already-existing claims (no physical write permission); exact replay returns the original ACK without another claim. Every new managed raw writer remains pre-reserved. Atomically persist claim/control/raw changes with source events; public auth and required physical proof must precede it. Do not weaken current Host/managed report gates.
8. New source-row raw classification and claims are immutable; source UPDATE/DELETE cannot refund a retained legacy claim or mutate its logical artifact. Data-only event metadata updates (e.g. report question session) still work. ACK does not release a claim. Explicit legacy expiry remains future proof-based work.
9. One migration transaction creates/backfills the new ledger and frozen source classification, changes accounting triggers and publishes version22. Reopen, exact replay and failed migration have exact once/rollback semantics. Update historical downgrade helpers by reversing v22 accounting before dropping its schema; do not erase meaningful assertions.
