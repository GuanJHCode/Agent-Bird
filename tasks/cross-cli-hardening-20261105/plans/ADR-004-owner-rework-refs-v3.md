# ADR-004 — owner_rework_refs_v3 (ADOPTED by /root, 2026-11-05)

Baseline 2347d34c; implementation owner /root/implement_t04, isolated tmp/t04. Root froze this contract; implement within stated file ownership. Existing v1/v2 fields/order/omitempty/digest/interpretation stay unchanged; first add fixed v2 golden bytes+digest. New protocol is explicit, no automatic upgrade of a task already carrying v1/v2 rework.

## Wire / authorization

HostHello append bool OwnerReworkRefsV3 json owner_rework_refs_v3,omitempty; runtime_hosts same INTEGER NOT NULL DEFAULT 0. Coordinator advertises owner_rework_refs_v3 independently. Existing request_changes IPC kind gains optional refs_v3 object; no new IPC kind or increased frame. Every phase retains exact control validation plus T07 authorizeOwnerAction and trusted transaction/replay snapshot checks; both legacy and refs paths receive actionCtx. Refs never confer owner authority.

refs_v3 request: phase(begin|chunk|commit|abort|gc), body_size, body_sha256, upload_id, offset, data ([]byte base64 max 16KiB decoded), plus existing complete candidate tuple/command ID (feedback/acceptance empty in wire). begin binds upload to controller_thread/run/task/source_revision/command/tuple/body_size/hash and returns opaque upload_id, no caller-selected path. Chunk has expected offset and idempotent byte comparison; server alone writes filesystem. Feedback document has version=3, feedback:string, acceptance:string. Per-body encoded max 256KiB, assembled input max 512KiB UTF-8, manifest max 8KiB, max refs=3 (immutable brief + <=2 decisions due existing attempts cap). Limits are new v3-specific limits and do not alter T03 16KiB adapter, 64KiB IPC, or legacy text fields. JSON overhead counts against body size. CLI request format adds explicit version:3, normal existing feedback/acceptance fields, using private large read with explicit max encoded bytes; upload body once in chunks, command checkpoint persists only tuple/upload identity/hash, not duplicate authoritative feedback. Existing version absent remains v2.

ReworkContext append RefsV3 *ReworkRefs `json:refs_v3,omitempty`, preserving all legacy bytes when nil. v3 retains previous candidate/source tuple, Source=owner, OwnerDecisionID; legacy feedback/acceptance remain empty. ReworkRefs version, owner, run_id, task_id, target revision, brief ref, conditions refs oldest-first. Each ref binds opaque object ID, owner/run/task/source_revision/kind/size/sha256 and authorized coordinator-owned absolute path. Context owner spec nil; decision stores small source tuple + input body hash/ref + receipt + exact adapter. Existing OwnerReworkSpec is not changed. Prompt marker mismatch fails closed; Host builds full prompt from refs before BuildInvocation. Original immutable full rev1 prompt is sealed once (not guessed/reparsed); subsequent rev3 reuses original brief and all prior feedback/acceptance conditions. Old v1/v2 rework cannot upgrade; explicit legacy invocation stays supported.

## Schema11 / durable lifecycle

Schema11 appends capability and rework_objects registry: id PK, owner/run/task/revision/kind, command_id, expected_size/hash, status reserved|published|pinned|abandoned|deleting, written_bytes, path identity (device/inode once file exists), with immutable bindings. rework_uploads binds command/tuple and object plus optional original brief. rework_pins references object and retry decision (or equivalent FK table). New quota triggers charge expected_size+4096 per object and4096 per upload metadata to run/global immediately on reserved INSERT, not when file appears; row remains charged through abandoned/deleting until successful unlink+directory fsync and DELETE. Existing storage_usage/triggers remain authority; metadata decision bytes still charged by existing retry trigger.

Begin transaction checks prior committed command FIRST (return original receipt independent of current provider/Host), then exact existing upload FIRST, then current source tuple/availability/new capability/quota. It reserves BOTH feedback and first immutable brief BEFORE creating staging. Commit transaction is short after publish and rechecks command/tuple/eligibility/Host, pins all refs, persists small decision, advances revision/ready sequence/revokes capability atomically; no schedule until commit. Published-but-uncommitted rows are protected and charged. Commit reply loss replays exact committed decision, even after provider loss/Host downgrade.

Server owns private rework-objects dir 0700 and object files 0600, exclusive/no-follow create, bounded regular owned nlink checks, fsync file and directory. Chunk operations serialized by DB mutex, no writer FD survives an RPC; retry reconciles uncommitted on-disk prefix against exact replayed chunk and completes remaining bytes. Immutable publish uses no-overwrite link+fsync+unlink-stage+fsync (same inode charged once), records identity; recovery permits only known same-inode staging/published pair. Finalize hashes/parses same bounded bytes; wrong/hash/truncated JSON fails closed. Body is never copied into DB or execution payload.

Abort only an authorized exact upload, mutually exclusive with chunk/commit under same mutex, marks abandoned; GC only explicit abandoned rows, zero pins, zero active/recovery upload references, no live writer (all writes hold same process-wide mutex and no FD survives return; coordinator singleton instance lock prevents a second process writer). GC commits deleting intent, proves complete known-link set, then atomically captures each source entry into one upload-scoped private0700 held quarantine using Darwin exclusive rename. It validates captured dev/inode/type/uid/mode/remaining nlink before unlinking only within that private namespace; fsync and held-original nlink0 precede registry DELETE. Unknown entries or capture-crash states retain content and charge with awaiting_cleanup_decision. A fixed upload prefix prevents new quarantine directories on retries; both objects share one. Empty successful barriers and charged upload tombstones remain bounded metadata until explicit owner retention/cleanup resolution, with optional v3 cleanup_reason; removed does not claim complete runtime cleanup. Non-Darwin GC is explicitly unsupported before quarantine creation. No mtime guessing, no GC of reserved/published/pinned, no automatic destructive recovery. Restart keeps pending upload recoverable; explicit abort removes recovery references. Tests inject reserve-before-write/partial-write/published-before-commit/commit-before-reply and GC interleavings.

## Host / gates / tests

Queue begin+commit, ClaimReady, PendingLaunches/reconnect check owner_rework_refs_v3. Existing v2 gate remains separately. Host local assembly rejects unsupported v3 or unknown version; validates source owner/run/task/revision/ref path under coordinator state rework-objects, opens no-follow beneath trusted root, owner uid/mode/regular/nlink1/device/inode, bounded read once then same bytes hash/strict parse/assemble, before worker sandbox. Worker receives assembled plain prompt only, never control root permission. All conditions remain oldest-first in deterministic fixed delimiters, no model summary/truncation. Host launch cap does not affect prior committed command replay.

Acceptance includes fixed v1/v2 bytes/digest, no payload growth across feedback, >64KiB feedback through chunk IPC, long Unicode/escaping bytes, quota before first write, failure cut points/restart, duplicate/reordered chunk, cross-owner/hash/path/tamper/missing body, GC commit concurrency, downgrade queue/claim/pending/Host, accept/reject/rework CAS, previous candidate base, last-attempt reviewability. Full Go normal/race/vet/build under fixed Go1.26.10; no real model.

Root adoption addenda: reservation charged_bytes=expected_size+4096; trusted state is passed by sourceHost, never inferred from a ref. Max assembled prompt is min(512KiB, unchanged actual transport/guard limit); final transport serialization is checked without truncation. Existing guard limits are not expanded. T07 uniquely owns server KindSubmit local-owner mode hunk.
