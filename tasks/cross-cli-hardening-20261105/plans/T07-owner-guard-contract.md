# T07 protected owner action guard (approved by root)

The confirmed resume counterexample commits resume_queued for a retired owner using only the old control tuple. Query/stop/ACK intentionally retain original bearer control semantics (docs/provider-runtime.md); they are outside this guard.

Guard: for resume/retry/rework/request_changes/accept/answer, server first validates exact task/controller/control token, then reads current DB run binding (run ID, origin context, PID, birth, task Host generation, local-managed classification). local-managed is derived solely from EXISTS owner_grants.id=run.origin_context_id, never delivery_mode or RPC assertion; original context survives rebind. Verify kernel process.Birth matches this current owner. For local-managed require authorizePeer kernel ancestry contains that PID/birth. Native runs require current owner live/birth but keep existing bearer delegation; no new native bypass. Errors: origin_owner_lost; owner_peer_mismatch; owner_binding_changed. Existing worker exclusion and unidentified-segment enrollment guard remain.

Native call-chain evidence: native-product-bridge.py/native_bridge bridge validates owner/helper/service/backend receipts plus lease/attachment, and drives delivery transport/history ACK; no code path issues accept/retry/rework/resume/answer (repository searches). Those decisions remain explicit parent CLI calls; native owner/helper may be independent processes, so imposing local ancestry rules on legacy native would break delegated transport without a new native proof protocol. Therefore only native owner liveness is tightened; no native identity claim is created. recover-host already checks local owner capability + run's origin/generation and later HostHello revalidates owner birth before registration. Preserve its dedicated recovery inspection path without the old-owner-live guard to avoid a recovery cycle. It never issues a task decision.

Store shared API in new owner_action_guard.go:
- OwnerActionBinding{TaskID,RunID,OriginContextID,OriginPID,OriginBirth,HostGeneration,LocalManaged} read via DB.TaskOwnerActionBinding(ctx,taskID,controller,controlToken).
- WithOwnerActionBinding(ctx,binding) context.Context carries trusted coordinator snapshot (not RPC fields).
- validateOwnerActionBinding(ctx,tx,*sql.Tx,taskID) error (actual Go signature: (ctx context.Context, tx *sql.Tx, taskID string) error), invoked immediately after BeginTx and before replay/decision checks in QueueResume, AnswerQuestion, ReviewResult, QueueRetry, QueueRework, QueueRequestChanges. Requery binding within the same tx, compare snapshot including HostGeneration; kernel birth recheck there. Rebind cannot race between comparison and mutation because its SQLite write transaction serializes. No snapshot means existing trusted in-process Store calls retain current behavior; every protected public Coordinator path always supplies snapshot. This is the existing service/library trust boundary, not a test/env bypass.

Ownership: T07 owns helper, coordinator protected action helper + server branches, decisions.go/rework.go hooks and tests. T04 owns QueueRequestChanges transaction hook only: after BeginTx/defer Rollback, `if err := validateOwnerActionBinding(ctx,tx,spec.TaskID); err != nil { return empty,err }`. Root integrates that one hunk after T04 snapshot. No change to refs_v3 contract or owner_rework public types.
