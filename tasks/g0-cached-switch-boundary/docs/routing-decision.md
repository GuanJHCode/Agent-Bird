# 待决策：回传目标的语义

状态：方案可审查，尚未授权更改交付契约，不实施自动路由变更。

cached03 的真实观察为 P→S→P→S。首次 fork 有 P/S lineage；cached P 有 thread/read(P)，但 cached S 只有 skills/plugin/account/command 等流量，没有目标为 S 的选择事件。四次独立 `/status` 能核对显示 ID；按当前合同，它们不能生成 attachment candidate。此处缺少的是选择身份，不是完全没有 RPC。cached03 整体因终止门禁失败保持 unknown，失败前选择边界的原始 trace 不变。

建议采用固定任务 owner 回传：任务创建时，从已核验的新建/恢复事件绑定原始主 thread P；后续输出、ACK 和恢复都绑定这项任务的 owner。用户暂时切到 side S 不改变任务归属，结果仍回 P。它不需要修改 Codex 本体或增加启动命令，也不宣称知道当前屏幕选中了谁。现有 owner/Go/Hook 证据可复用，但从“跟随当前显示”改为这一语义需要用户确认。

若必须跟随当前显示，可改为每次切换后由用户显式确认目标，并记录为人工确认；这会增加用户操作，不能宣称自动识别。若保持自动跟随且仍禁止修改 Codex，则当前固定版本证据不足，该功能继续暂停。不能扩大后台 RPC 白名单来补出不存在的目标 ID。

本决策与用户级启动注册分开：安装 LaunchAgent 可以解决入口按需拉起问题，但不能让网络代理看见 TUI 纯本地的显示选择。用户级注册及实际账号登出仍未授权。
