Base: integration bd5bd8e, schema18. ROOT owns integration and physical macOS/Docker verification. ## Storage and delivery contract

- Default summary retains only the existing allowlisted aggregate. Explicit immutable task `diagnostics: {version:1, mode:"detailed"}` authorizes stdout/stderr capture. It is independent of adapter/execution-policy hashes, included in submit/config preparation identity and signed launch; budget revisions cannot change it.
- All segments of one attempt share a rolling log. Retry uses a new attempt/account. Retained data, one write staging chunk and one unacknowledged read page together are capped at 20 MiB. Use 318 physical chunk slots of at most 64 KiB, one 64 KiB staging slot and one at-most-64 KiB serialized read delivery. Two at-most-64 KiB manifests have a separate fixed 128 KiB metadata reservation. Keep bounded RAM (8 queued records of <=32 KiB plus one <=64 KiB assembly buffer); never run disk or RPC work under the pipe/capture mutex.
- Each chunk holds packed stdout/stderr records with stream offsets and segment identity. Small writes share a chunk. A periodic partial flush replaces the current chunk, preserving the record prefix. Only full chunks or segment changes advance slot sequence; tiny writes must not consume 318 slots prematurely. Chunk format/header/hash and exact scope bind run/task/attempt/producer/policy; no arbitrary path or stdin/env capture.
- One writer lock per attempt prevents concurrent/resumed writers. Updates have a separate bounded lock readable across processes. Every file is owner-only, regular, single-link, opened without symlink following; directories are 0700. Unknown entries, permissions, scope, hash, length, sequence or format drift fail closed. Fixed slot paths, one fixed stage path and bounded manifest count prevent file-count growth.
- Durable intent before slot replacement records old/new descriptor and exact resulting manifest. File sync + rename + directory sync precede committed manifest. Recovery chooses only exact old/new hashes, never guesses a torn record as valid. Readers may return prior committed data and explicit incomplete/truncated status; pending read bytes are copied into Store, so rolling never overwrites an unACKed delivery.
- Public raw reading is a separate owner-control-authorized command; ordinary status/summary/collect expose metadata only. A page is <=32 KiB raw and <=64 KiB encoded. At most one pending page per attempt is persisted transactionally and replayed exactly after ACK loss; its ACK affects neither task decisions nor launch authority. Cursors bind attempt and chunk/record position; evicted ranges report an explicit gap and next retained position. Read/ACK remains data-only for UNKNOWN/dead owner.
- Log quota is pre-reserved transactionally before a detailed attempt's first grant. Resume reuses the same reservation; restart/ACK replay cannot reset or double-charge it. Diagnostic data accounting is separate from 16 MiB run /128 MiB user control accounting. User artifact allowance must include detailed reservations and registered output artifacts (default 2 GiB), without charging Git blobs/worktree as copied artifacts. Indexed manifest is already contained in result-output.bin; hydrated review scratch and recovery/control metadata remain separately classified.
- Reservation release requires an explicit durable deletion intent, closed original writer or retained UNKNOWN, reference/pending-delivery check, exact owned-file deletion and directory sync, then Store release. Never assume SQLite commit and unlink are atomic; restart reconciles the original intent. Until deletion is proved, retain the reservation.
- Disk/queue failure keeps stdout/stderr draining, records exact truncation where observable, and stops further execution through existing owned-stop/fatal paths for storage failure. An unwritable disk cannot promise a new persistent error; existing durable state stays incomplete and recovery must expose it. Summary metadata write errors must become visible instead of being discarded.

## Contract review corrections (ROOT decisions)

1. Exactly two manifest names are allowed: `manifest.json` (canonical) and `.manifest.stage` (atomic-replace temporary), plus the separate `chunk.stage` data file. A transition stores one full current descriptor vector and one old/new slot delta, not two unbounded full vectors. Under the same held update lock: write/sync pending generation g+1 to `.manifest.stage`, rename to canonical, sync directory; then write/sync `chunk.stage`, rename to the fixed slot, sync directory; finally write/sync resolved generation g+2 to `.manifest.stage`, rename to canonical, sync directory. Never overwrite the canonical pending file in place. A crash during final promotion leaves either the canonical pending intent or resolved manifest, both valid; `.manifest.stage` is never an authority. Before any next transition, reconcile the canonical pending record against the target slot's exact old (including absent) / new hash; neither match is corrupt/incomplete, not a guessed committed chunk. A matching new file rolls forward; matching old rolls back. Untrusted stage files are not silently removed. Header/descriptor bounds are checked before each write so each manifest stays <=64KiB. No third manifest/promotion file is created.
2. Public read/ACK uses the already existing run-control credential plus `controller_thread`/task authorization (`store.ValidateTaskOwner`), not the execution owner's private control key or liveness. Existing status/collect has the same distinction; no new surviving execution authority is needed. Attempt must belong to the authenticated task and fixed detailed policy/producer. The exact pending receipt binds attempt, request revision, delivery ID, serialized-body SHA256, start/end cursors and gap. ACK verifies all bindings transactionally; it cannot skip a pending page or change task decision/launch state. Exact duplicate latest ACK is retained and idempotent; older already-advanced ACKs return explicit stale status without any mutation. New read cannot replace an unACKed page, even with a different cursor/request ID.
3. Detailed attempt reservation is explicitly `20 MiB + 128 KiB`, with no borrowing between data and manifest pools. The data pool includes the full serialized pending delivery (body, cursor/hash/scope/envelope), capped at64KiB, not just raw log bytes. ACK frees only that pending-page use; the full namespace reservation remains until authorized deletion is proved. The user2GiB allowance is for managed retained artifacts/reservations, not an OS quota over worktree/Git blobs or arbitrary provider scratch. Managed artifact writes must receive an upfront reservation or use an intake writer before writing managed files; provider-prewritten inputs are bounded intake sources, not proof of prior quota admission. M3 must implement the managed intake/reservation boundary for legacy report artifacts before the total allowance can be called complete. Registration-only accounting is insufficient and remains a required implementation item, not a waived gap.

B3 mapping is investigation only: a report-only seal excluding runtime Exited/question evidence is insufficient for F10. Preserve the full original event/report seal, writer fences, original Wait/tree or UNKNOWN facts and retirement/new-incarnation requirements; do not substitute exact replay of already-committed report rows for dead-owner recovery.
