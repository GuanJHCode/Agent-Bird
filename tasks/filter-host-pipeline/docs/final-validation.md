## Implemented scope

Darwin admission supports an initial pinned Claude/AGY-shaped `kind=provider` implementer with a fresh auto workspace, followed by a standalone `kind=candidate` validate action. The validator requires the exact manifest, one accepted v1 dependency, a separately reserved sealed native tool, and an exactly zero Target. No filtered review, compose, integrate, rework, continuation or automatic retry is admitted. CLI typed-profile guard recognizes this narrow shape; native acceptance below uses actual Store/Host APIs, not a real Provider or public CLI protocol run.

Host freezes all nested grant authority and exact original payload bytes before invocation callbacks, snapshots the invocation, creates its journal with O_EXCL before Broker/source/Git work, and refuses every pre-existing journal. Producer preparation/freeze and validator materialization use only their original live source/Broker/handles. Finalization requires the original process start timestamp and original Wait/tree proof; UNKNOWN cannot produce cleanup/refund authority. Accepted candidate identity, source payload, receipt hash, filter manifest, B/R hashes and zero target authority are checked. Each validator Verify also checks the source private ref through its retained original journal and source context, including after the result journal callback.

Producer `provider_result` is ingress-only; actual CandidateArtifact envelopes decode without propagating that text downstream. Candidate outer fields and journal attachments reject duplicates/case aliases/unknown typed fields. The journal-local decoder preserves legitimate opaque record values and typed file inventories without widening the global bridge decoder.
