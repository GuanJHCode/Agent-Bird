## Broker stream input (no fourth file)

Add Go-only `StreamLoadResult { SHA256 string; Bytes int64 }` (both `json:"-"`) and `ResourceBroker.LoadStream(context.Context, int, func(io.Writer) error) (StreamLoadResult,error)`. This trusted Host callback is synchronous: any original Git process it starts must be stopped/waited/tree-proved before returning. The callback must not reenter the same broker. It receives a revocable writer, never a descriptor, path, seek method or a serializable capability. Caller cancellation is permitted; no invented never-started or terminal proof follows from a callback or journal alone.

Under the existing broker mutex: validate slot/callback/live usable state and `checkAll`; journal `loading` before altering any slot or invoking producer; mark target uninitialized; truncate to zero; stream only through a private writer. The writer uses its own mutex plus `WriteAt` at a bounded offset, checks context, refuses a write that would exceed 16MiB, checks short writes, and records the first error. After callback returns, close/revoke that writer while holding its mutex, so retained or racing uses cannot mutate a slot after return. A nil callback result cannot erase a writer's sticky error. A panic guard must first revoke the writer and set broker UNKNOWN, then re-panic; a caller that recovers cannot reuse or clean this loading broker. There is no additional file/node or unbounded buffer.

If the callback reports `process.ErrProcessTreeUnknown`, preserve `errors.Is` and mark broker UNKNOWN; no cleanup/release. Broker inventory, identity, sync, journal or actual slot I/O failure also UNKNOWN. Ordinary producer errors (whose original process was confirmed terminal by the trusted caller), context cancellation and overflow keep the slot invalid and make this broker failed. In that known-error case use a fresh bounded cleanup context, truncate/sync/refresh the slot, recheck the full inventory, then durably write `terminal`; only then is exact existing Cleanup permitted. Do not return a stream hash or permit subsequent ReadSlot/Transform on a failed broker. Any failure during this finalization upgrades to UNKNOWN and preserves the original error. Success syncs/refreshes/checks all/writes `ready`, then marks initialized and returns actual held-slot hash and byte count. Stream load does not set filter/provider StartedAt/TerminalAt; raw Git has its own original process proof but does not change the frozen filter/provider active-span contract. Cold journal is never adopted, regardless of phase.

At most five focused subcases (including panic→UNKNOWN/recovered caller cannot reuse): successful multi-write load and retained writer revocation; overflow ignored by producer cannot succeed; partial ordinary error produces no usable bytes and allows exact known cleanup; partial original process UNKNOWN keeps resources and errors.Is. One targeted race set plus package vet/build, reused broker lifecycle evidence, no full-suite sweep. Small interface doubles may be updated only if compilation shows a necessary dependent stub; return that shared-file need to ROOT first.
