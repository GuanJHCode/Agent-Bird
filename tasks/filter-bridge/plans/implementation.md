# Exact live filter transformation session

Base: integration `e90f06f630a641662aedac5ff62e9202497625a4`. ROOT owns this worktree. No public filtered integrate, IPC/helper endpoint, process launch API or merge transition is opened by this leaf.

The original Broker already provides bounded slot loading, sealed tool execution with original Wait/tree, and resource ownership. The missing bridge authority is a finite set of exact authorized exchanges. A future Git helper may route requests to this session; inherited endpoint/token/FD values are not transformation authority. Even a hook that can route a request may only consume an exact approved exchange or fail the session.

## Frozen private API and behavior

Implement in `internal/gitfilter/transform_session.go` so the session retains the original `ResourceBroker`, including its State, without acquiring cleanup rights. Construction receives that live object, its expected complete StreamBinding, a cloned validated manifest and a copied list of `ExactTransformPermit` values. The Host is responsible for deriving permits from authenticated B/R evidence. None of these DTOs reconstructs a Broker or authenticates a grant. Before any journal/state mutation require manifest.Digest() == expected.ManifestSHA256 and broker.Binding() == expected; clone the authenticated manifest and use a version/domain-separated canonical permit-list digest.

Each permit fixes path, clean/smudge operation, actual input SHA256/bytes, expected output SHA256/bytes and MaximumCalls (1..16). At most 1024 permits and 1024 total calls; sizes are 0..16MiB, paths belong to manifest.Paths. Reject duplicate input selectors `(path,operation,input hash,size)` even if outputs differ. Canonically sort/copy permits and hash their complete list for journal binding. The session still shares the Broker's original 4096-step cumulative limit; it does not reset or promise the remaining budget.

`Exchange(ctx, sequence, path, operation, produce func(io.Writer) error) ([]byte,error)` uses strictly consecutive sequence numbers starting at 1. Caller cannot select a slot, tool, argument, scope or filesystem destination. Require a finite caller deadline and a synchronous producer; as with Broker.LoadStream, the future stream adapter must make blocking reads interruptible. No detached read goroutines or false timeout/Wait proof. Production sequence is fixed LoadStream(0), Transform(op,0,1), ReadSlot(1).

Before slot mutation, require a known path/op and available budget and durably journal intent. Actual LoadStream hash/size selects the permit and consumes its call; an unknown input never starts a tool. Check Result.Accepted/Started, original timestamps, WaitProved/TreeProved, Unknown, actual input/output hashes/bytes against the permit. Read output into one bounded buffer, independently hash/count it, and publish bytes only after all guards and a durable terminal record pass. The buffer is bounded to expected output bytes, never above 16MiB. An output mismatch returns no bytes.

Journal receives copied scalar-only records containing phase, sequence, complete binding fields, permit-list digest, path/op, actual input/output hash/size and original tool terminal flags. Recheck Binding and Broker.State before/after journal callbacks and every Broker operation. A callback cannot alter the expected list or produce successful output after binding drift. Failures are sticky, including wrong sequence/path/op, exhaustion, callback error and cancellation. A terminal-journal failure after slot mutation marks session uncertainty; no output/retry.

Use a small state mutex to reject concurrent Exchange (and poison the session), rather than allow slot interleaving. Close only revokes this session; it never closes/cleans the borrowed Broker. An in-flight Exchange retains original execution responsibility and must finish under its caller context; revocation before the success commit prevents publishing its output. After terminal journal and final Binding/State/context checks, acquire the state mutex: closed/poisoned or a changed active sequence rejects with zero output; otherwise commit the successful call count/sequence and clear inflight under that lock. This is the success linearization point. Close/poison before it wins; a later Close only revokes future calls and cannot retract committed bytes. The terminal journal records the tool exchange, never claims bytes have been published. Do not hold the state mutex across external callbacks. Result.Unknown, Broker.Unknown or a started tool lacking original Wait/tree/timestamps makes the session UNKNOWN. Future Host cleanup must require terminal outer Git, no handlers and a known session/Broker; this leaf does not claim that future contract implemented.

## Minimal verification

One focused portable race batch: exact output + original/copy/journal contract; bad binding/permit; wrong path/op/sequence/exhaustion; wrong actual input starts zero tools; output mismatch publishes zero; journal callback drift/failed intent/failed terminal; unknown/missing Wait/tree, cancellation, concurrent revoke/Close. Use a recording fake only for these deterministic boundary tests and label it synthetic.

One new Darwin native top using the existing small Broker fixture, not the expensive Git/Host chain: real XOR tool, exact B→R smudge and R→B clean, original Wait/tree, returned bytes/hash and ordinal, known Broker state; session Close leaves Broker usable and original Host fixture explicitly cleans it. The wrong-input branch shares only the built actor; it MUST use a fresh Broker and assert EverStarted remains false before/after, then known cleanup. The positive Broker cannot prove this negative. No existing long native reruns. Whole Mac/Linux builds and narrow vet run only after final relevant changes. Independent review must cover production and oracle; retain all raw source/argv/output/counts.

## Deferred boundaries

The next carrier should consider Git filter.process (clean/smudge, no delay), with bounded framing and an authenticated original-owner local channel. Its helper/outer Git Wait/tree and target before→after transition need separate implementation and qualification. Normal merge/hooks/signing remain unchanged. This leaf grants no target mutation, cleanup, replay/recovery or public wire authority.
