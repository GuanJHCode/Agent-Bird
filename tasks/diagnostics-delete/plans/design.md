# F02 explicit completed-attempt diagnostics deletion (draft)

Scope: owner-authorized explicit deletion of managed detailed diagnostics for a completed task, with no active/unknown segment and no reading/pending diagnostic page. Not automatic TTL/GC, report/candidate artifact deletion, legacy_pending adoption, failed/unresolved execution, physical2GiB or overallF02 completion. Default retention is unchanged; a specific authenticated delete request is an explicit owner disposal decision. No live user data is touched by implementation/fixtures.

## Public and Store contract

Add diagnostics-delete request Version1, TaskID, AttemptID, RequestID, ExpectedRevision, plus existing control-file authority in CLI. No user-supplied path or quota amount. Reuse diagnostics token/JSON limits and original run/controller/token/task/attempt/producer/policy/reservation authorization. One immutable command per reservation, and a run/request ID cannot name a second command. Exact retries retain original plan and completion bytes; changed arguments conflict. Reads after deleting fail unavailable; after released fail expired. Existing ACK never starts deletion or frees bytes.

Admission requires task.status=completed (the current accepted completion contract), a bounded set of original attempt segments all runtime/segment exited, no current/resumable execution or UNKNOWN, diagnostic phase=idle and exact next_revision, and the same reserved/active diagnostics reservation. This is intentionally narrower than deleting a failed/paused attempt; rework creates another attempt and cannot reclaim this namespace. Confirm exact terminal/accept semantics against Store before implementation.

Use schema31 diagnostic_deletions: immutable original identity/request, saved Store root nodes, canonical physical plan, completion template, physical tombstone bytes, and phase prepared->removed. No migration backfill/adoption. All TEXT/BLOB UTF8 lengths plus fixed integer costs and the retained physical tombstone bytes are control-accounted at prepare; completion template is charged upfront. Reservation state reserved/active->deleting in the same transaction as intent; it remains counted at the full reserved maximum through all uncertainty. Only confirmed filesystem deletion followed by the final transaction changes deleting->released. Metadata/tombstone remain accounted. Return released reservation bytes separately from removed logical file bytes; do not claim filesystem blocks or physical disk reclamation.

Flow: authenticate read-only snapshot -> acquire existing filesystem writer/update locks and capture exact closed namespace plan -> new same-connection Store transaction re-authenticates terminal state/phase/revision/reservation/root, charges and persists intent, CAS deleting -> commit/postcheck -> filesystem deletion -> final Store transaction validates exact intent/root and held physical proof, marks removed/releases reservation once -> exact response. No Store mutex/SQL transaction spans filesystem reads/unlink/fsync; namespace locks may span the short Store transactions. Concurrent read wins its reading fence or delete wins deleting CAS, never both. Concurrent deletion is serialized by existing namespace locks. First commit error performs no deletion. Final commit error leaves a replayable deleting intent; quota remains retained unless the actual commit succeeded. Use audited ownerTransaction physical rollback/discard and a dedicated Store root pre/post guard on the same physical connection, without weakening existing initial-owner protocol.

## Filesystem contract and proposed interface

Managed root is derived from saved Store state/host-spool/producer/attempt/.diagnostics and exact Scope.Hash. Never create a missing namespace, writer lock or update lock. Take exclusive existing writer and update locks; verify canonical path/no symlinks,0700 directories,0600 same-owner single-link files, held/named inode identities. Initial plan requires a valid exact-scope manifest Closed=true, no Pending/unclean stage, and complete bounded slot hashes. No active writer can prepare a plan. Use one reusable ChunkBytes buffer (20MiB data is not collected in memory).

Proposed internal diagnostics API (freeze after review): OpenDeletion(ctx, root, scope, commandID, savedPlan []byte) (*DeletionLease,error); lease.Plan() returns canonical bounded immutable bytes; lease.MarkerBytes() returns exact permanent metadata cost; lease.Remove(ctx) returns canonical completion proof; lease.VerifyRemoved(ctx) checks marker and absent original files while retaining locks; lease.Close releases FDs. savedPlan is only read from authenticated DB, never public input. Fresh OpenDeletion only inspects; Remove is called only after durable Store intent. Typed internal proof constructors/private fields prevent public JSON from granting deletion authority.

Plan binds root/namespace/lock dev+ino+uid/mode plus each recognized data filename, inode identity, size/time and SHA256, scope, command ID and a frozen random stage basename. Maximum original inventory is fixed SlotCount+manifest/locks; unknown files, symlinks, hardlinks, changed content or namespace replacement reject. On replay keep the original plan; do not recompute/adopt replacement files or refund from current size.

Before unlinking anything, publish a private immutable deletion marker binding command/scope/plan hash: deterministic bounded body, unique frozen stage, file fsync, no-replace rename, directory fsync. Exact torn stage prefixes can recover only under the saved intent/private directory identity; conflicting marker/stage remains blocked. Marker makes ordinary Reader/OpenWriter reject the retired namespace (existing unknown-file fail-closed path is sufficient). No marker or durable intent means missing original files are not accepted as proof of authorized deletion.

Then unlink only the original planned data files using held-FD relative operations after identity+content checks; manifest is last. Replays accept missing planned files only under the exact marker. Verify inventory remains exact, fsync directory, retain marker plus original empty writer/update locks and namespace directory permanently as bounded accounted tombstone. Never unlink lock files, rmdir the namespace, recursively remove an unknown path or delete a recreated identical-byte/different-inode file. New files or partial errors retain intent/quota and remaining evidence. Store finalizes only after VerifyRemoved under the same held locks. This prevents a completed deletion from enabling an old signed writer to recreate the namespace.

## Validation / ownership

Freeze exact terminal gate, schema/cost and filesystem interface before parallel implementation. ROOT owns Store/schema/public IPC/CLI and integration. A separate isolated writer may own internal/diagnostics deletion implementation/tests after contract review; no shared-source worktree writing.

Minimal evidence: owner/phase/revision/UNKNOWN refusal without filesystem effects; actual closed managed data delete->expired read + exact command replay/quota once; concurrent read/delete gate; actual COMMIT error before deletion and after FS removal; physical partial deletion reopen/replay plus inode/unknown-file and live-writer refusal. Prefer small grouped regressions and one existing public diagnostics flow extension; reuse existing capture/read/ACK/accounting and owner transaction tests. One controlled process crash exercises durable marker/partial-removal recovery if the implementation adds crash recovery claims. Mac/native Linux only; no real models/accounts/install changes/push.

Open points for review: whether the completed-task gate also needs explicit delivery/pin quiescence despite diagnostics never being candidate/report input; which saved root helper can be reused without introducing initial-owner-specific authority; exact proof persistence needed to reject replaced intermediate directories; permanent tombstone accounting and possible later bounded metadata compaction (out of scope now).
