# Host slot retention

Goal: finish bounded owner-authorized retention for Host terminal/progress managed slots, preserving immutable events/refs/proofs and physical tombstones. Success uses exact terminal consumption plus confirmed exit and 30 days. Failure requires explicit resolved/abandoned for the exact reservation and a reason, then seven days after the latest terminal/consumption/resolution time. Resolution covers the fixed one terminal slot or 21 progress slots in that reservation, not arbitrary paths. UNKNOWN cannot be resolved into cleanup authority.

Schema40 creates immutable cleanup authority only in the new dispatch reservation transaction; no historical backfill. Legacy registered objects retain their saved physical proof. Legacy unregistered populated slots remain unowned; missing slots may only be fenced with a trusted original Host namespace proof. New authority permits bounded discovery of strictly managed fixed-slot orphan objects. No general directory scan or arbitrary path deletion.

Cleanup operates at reservation granularity. A prepared header fixes owner/facts/Store root/Host namespace/class/count/discovery authority and prepays a bounded budget for every child plan, marker and row. This is committed before FS object/lock creation. Each slot is locked without a DB lock; then its exact child plan is committed, physical removal performed with the slot lease and a final DB write transaction, and child completion persisted. All fixed slots must carry exact removed/absent-fenced proof before the reservation is released. Unknown slots keep the full reservation. No partial refund from retained_bytes.

Current consumer protection is deliberately conservative: all tasks/segments in the run and any live successor run must be terminal, exact runtime/report ACKs settled, no open question/continuation/retry/rework or explicit pin. Facts bind immutable terminal event vectors and current revision/owner. SQL fences reject new references during prepared deletion; committed reads reject retired target slots. Physical marker prevents even a stale Host grant from recreating a retired slot. Progress read projections stop advertising removed bytes while retaining history.

Public resolve/plan/apply and default-off gc enable/disable/status mirror the established report control-file/request pattern. Plans are bounded, owner-bound and saved exactly by GC; old binding cannot resume a prepared plan. Independent FS worker owns only artifacts; root owns schema/Store/public integration. Focused quota/retention/replay/reference tests and a single compact public smoke test, no full matrix or real Provider.

Remaining separate scope: candidate/shared private-ref TTL maintenance, legacy unowned resource manual classification, native Provider/TUI/other OS acceptance. This batch does not collect live user runtime data.
